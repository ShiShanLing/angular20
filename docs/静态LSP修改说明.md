## 必须保住的结构

`静态` 是住宅出口，类型 socks5，服务器 `216.175.200.47:443`。不要删，也不要改服务器。它的 `dialer-proxy` 必须指向 `静态前置自动切换`。这个地址拒绝大陆 IP 直连，所以必须先从日本或美国节点拨出去，再连它。

三个策略组：

| 组 | 作用 | 类型 |
|---|---|---|
| 静态前置自动切换 | 只给「静态」当拨号前置，`hidden: true` | **fallback** |
| 日美自动切换 | 直接当出口，`hidden: true` | url-test 可以保留 |
| 静态住宅代理 | 分流规则的总出口，手动选择 | select |

`静态住宅代理` 的成员顺序保持：`日美自动切换`、`静态`，然后是各条日本和美国节点。

`rules:` 以及后面的全部规则不要动。

## 从新订阅搬节点

只搬名字里带「日本」或「美国」的真实节点，按订阅里的原顺序全部搬过来。不要按延迟测试结果删节点。

不要搬这些：

2. `静态前置自动切换`
3. `日美自动切换` 和 `静态住宅代理`

`静态` 那一段原样留下，放在 `proxies` 的第一条。

## 前置组为什么必须用 fallback

`静态前置自动切换` 不是出口，它只负责帮「静态」把连接拨出去。

`url-test` 每次只拿当前延迟最低的一条去拨。这一条这次没连上，整次请求就超时，要等下一轮测速才换节点。组里其他节点是通的，这次也用不上。`tolerance: 50` 还会在延迟接近的节点之间来回切，前置一切换，静态这条连接就断。界面上就是「明明有节点，前置偶尔超时」。

`fallback` 会按列表使用第一条可用节点。当前这条拨号失败，立刻试下一条。这才是前置该有的行为。

`日美自动切换` 自己就是出口，不负责给「静态」拨号，所以它继续用 `url-test` 没有这个问题。两个组的节点名单可以相同，类型不要写成一样。

前置组写成：

```yaml
- name: 静态前置自动切换
  type: fallback
  hidden: true
  proxies:
    # 日本和美国节点，与订阅顺序一致
  url: https://www.gstatic.com/generate_204
  interval: 40
  lazy: false
```

这里不要写 `tolerance`。那是 `url-test` 的字段。

## 测试时怎么判断

直连 `216.175.200.47:443` 时，端口可以打开，但服务端会回 `Mainland China IP ... banned`。这只说明当前网络被拒绝，不说明这条住宅代理坏了。

测「静态」必须走一条日本或美国前置，再连这个地址。这样测的时候，配置里的 socks5 可以连通。同一个地址也接受带账号的 HTTP 代理，但配置里保持 socks5，不要改成 http。

延迟数字是整条链路的耗时：先到前置，再到住宅代理，再访问 `https://www.gstatic.com/generate_204`。

检查配置语法用 Clash Verge 自带的内核：

```bash
"/Applications/Clash Verge.app/Contents/MacOS/verge-mihomo" -t -m \
  -d /tmp/clash-cfg-test \
  -f "<当前本地配置的绝对路径>"
```

`-d` 那个目录里放 Clash Verge 数据目录已有的 `geoip.dat` 和 `geosite.dat` 的链接，并加上 `-m`。否则内核会去 GitHub 下载 MMDB，本机经常下不动，检查会误报失败。

临时拉内核测延迟时，监听端口不要用 7890、7891、9090。测完关掉进程，并删掉带账号的临时配置。

## 改文件时的写法

用脚本改，不要整份重新序列化。`rules` 很长，整份重写容易把引号和规则弄坏。

做法：

1. 从旧文件切出开头（`proxies:` 之前）和 `rules:` 之后的原文
2. `静态` 那一段按原文字保留
3. 从新订阅筛出日本、美国节点，转成 YAML 后，每一行前面补两个空格，挂在 `proxies:` 下面
4. 再写三个策略组
5. 把 `rules:` 原文接回去
6. 用上面的 `verge-mihomo -t` 检查通过

空的 `flow`、`up`、`down` 不要写成空白值，直接省略。

说明文件里不要记录密码、UUID、混淆密钥、订阅地址。
