# Word 转 HTML 处理方案：AI 项目说明

本文件是 AI 使用 `word转html处理方案/` 小项目时的入口说明。AI 开始任何处理、排错或规则修改前，都必须先完整阅读本文件；离线 Node.js 程序本身不会读取本文件。

## 项目目的

本目录用于把 Microsoft Word 导出的知情同意书 HTML，安全转换为：

1. `legal_permission` HTML 正文片段。
2. 可放入 JSON / `core-data='...'` 的转码加转义 TXT。
3. 机器可读的处理校验报告。

处理该项目时必须使用 `脚本/consent-word-html/` 中随项目提供的固定规则，不得临时创造另一套转换流程，也不得依赖用户主目录下的全局 Skill 副本。

## 目录职责

```text
word转html处理方案/
├── AGENTS.md          AI 必须遵守的项目说明
├── 同意书HTML转TXT工具.html 供人工操作的静态辅助页面
├── 输入/              只存放待处理的 Word HTML 及其资源目录
├── 输出/              只存放处理后的 HTML、TXT 和校验报告
├── 可视化版本/         本地浏览器界面、服务端和启动器
└── 脚本/
    ├── 处理WordHTML.js 固定处理入口
    ├── 使用说明.md     项目的使用方法
    └── consent-word-html/
        ├── SKILL.md     AI 的固定工作流
        ├── references/  转换契约、使用说明和失败回退规则
        └── scripts/     项目内置的离线处理核心
```

`同意书HTML转TXT工具.html` 是合并前的旧静态辅助页，仅作为历史备份保留。新的人工操作入口统一为 `可视化版本/`；AI 执行自动处理时仍必须使用 `脚本/处理WordHTML.js`，不能用页面替代固定脚本和校验报告。

`可视化版本/` 是与命令行版并存的离线浏览器入口，统一提供 Word HTML 处理、HTML → TXT 转码加转义、TXT → HTML 反向解析三个页面流程。它必须调用同一个 `脚本/consent-word-html/scripts/process-consent-word-html.js` 转换核心，不得复制或重写转换规则。可视化处理只能使用系统临时目录接收页面选择的 Word HTML，处理结束后立即清理，不得读写命令行版的“输入”或“输出”文件夹。用户通过浏览器明确授权“工作文件夹”时，页面可以把已经通过校验的 HTML/TXT 写回该文件夹；遇到同名文件必须先提示并取得用户明确确认，未经确认不得覆盖，且不得修改或删除源文件及资源文件。

## AI 开始处理前

1. 先读取 `脚本/使用说明.md`。
2. 完整读取 `脚本/consent-word-html/SKILL.md`，并遵守其引用的 `references/contract.md` 转换契约。
3. 检查“输入”文件夹中的 `.html` 或 `.htm` 文件。
4. 如果只有一个 HTML，直接处理；如果有多个而用户没有指定，先询问具体文件，不能自行猜测。
5. Word 生成的 `.fld`、`.files` 等图片资源目录不参与转换；脚本固定移除全部图片引用。

## 固定执行方式

每次运行或重新运行固定脚本前，必须先清空本项目“输出”文件夹中的全部内容，但保留“输出”文件夹本身。清理范围必须以本文件所在的项目根目录为基准，严格限定为：

```text
输出/
```

不得清理、移动或修改“输入”文件夹及其中任何文件。完成输出清理后，再执行下列固定入口。

在本项目根目录执行：

```bash
node "脚本/处理WordHTML.js"
```

当“输入”文件夹中有多个 HTML 时执行：

```bash
node "脚本/处理WordHTML.js" "需要处理的文件.html"
```

不得跳过该入口后自行编写临时转换脚本。

## 可视化版本

在 macOS 中可双击：

```text
可视化版本/启动可视化版本.command
```

也可以在项目根目录运行：

```bash
node "可视化版本/server.js"
```

服务必须只监听 `127.0.0.1`，不得把文件发送到外部网络。页面转换或往返解析失败时必须显示固定核心返回的具体错误；只有对应流程的全部校验通过后，才能显示下载按钮。Word HTML 处理结果可以带入 HTML 编辑区，但用户编辑后的内容必须重新执行 HTML → TXT 校验，不得沿用修改前的报告。

## 输入和输出约束

- “输入”文件夹中的内容视为只读，禁止覆盖、重命名、移动或删除。
- 所有生成结果只能写入“输出”文件夹。
- 每次执行固定脚本前必须清空“输出”文件夹，确保其中只保留本次生成的结果。
- 每次处理必须生成 HTML、TXT 和 JSON 报告三个文件。
- 三个输出文件必须使用同一个六位随机编号，便于识别同一次处理生成的文件。
- 不得把临时文件、测试文件或中间调试文件留在“输入”文件夹。

## 必须保留的内容

- 正文文字、段落和空段落。
- 表格、粗体、下划线和颜色；图片是固定移除项，不属于必须保留内容。
- 字号、粗体、斜体、颜色、margin、缩进和行高等标准样式。
- 默认移除字体家族选择，让浏览器使用页面继承字体或用户设备默认字体；不得因此删除字号、粗体或斜体。
- 链接的可见文字与原有视觉样式；只取消跳转能力。

未经用户明确要求，禁止删除空段落、调整 margin、重建编号、修改标题位置或进行任何推测性排版优化。字体家族选择、全部图片引用、Word 私有 `@list` 规则、旧式 Word/IE CSS 声明（`layout-grid` 系列、`tab-stops`、`text-underline`）的移除、CSS 选择器及声明中无意义结构空白的安全压缩，以及最终生成 HTML 中全部 CR/LF 源码换行字符的移除，是本项目明确的固定规则，不属于推测性修改。后代选择器、属性值、函数表达式、CSS 字符串内容及转义字符中的必要空白必须保留，源码换行移除不得删除 `<p>`、`<br>` 或空段落等实际页面结构。

## 完成条件

只有固定脚本退出成功，并且 JSON 报告中的检查全部为 `true`，才能称为处理完成。AI 的最终回复必须列出：

1. 输入文件绝对路径。
2. 输出 HTML 绝对路径。
3. 输出 TXT 绝对路径。
4. 校验报告绝对路径。
5. 移除图片数、禁用链接数、TXT 裸单引号数。
6. JSON 解析、逐字符解码、可见文字、内联样式、文档外壳、Word 私有 `@list`、全部图片和可点击链接的检查结果。

不能只回复“处理完成”。

## 失败处理

- 脚本失败时停止自动交付，不得绕过校验。
- 明确报告失败原因和对应文件。
- 阅读项目内的 `脚本/consent-word-html/references/ai-fallback.md` AI 受控回退说明。
- AI 只能制作候选副本和差异报告，且只能写入“输出”文件夹。
- 存在未解释差异时，不得称为“无损结果”。
