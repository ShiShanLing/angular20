# Word HTML 处理方案

这是一个完全离线的小工具，用于把 Microsoft Word 或 WPS Writer 导出的 HTML 转换为：

- 可检查、可继续编辑的 `legal_permission` HTML 正文片段；
- 可放入 JSON / `core-data='...'` 的转码加转义 TXT；
- 命令行模式下生成的机器校验报告。

> [!IMPORTANT]
> 转换成功表示正文结构、JSON 往返和安全检查已经通过，不代表页面样式与原 Word 文档完全一致。项目会按固定规则移除所有图片引用；Word/WPS 在导出 HTML 时也可能改变分页、缩进、编号、行高和表格。生成 HTML 后，必须对照原 Word 文档检查并按实际展示环境调试样式。

## 一、运行条件

- 一台已安装 Node.js 的电脑；
- Microsoft Word 或 WPS Writer，用于把 `.doc` / `.docx` 导出为 HTML；
- 输入必须是 `.html` 或 `.htm`，本工具不直接处理 `.docx`、`.pdf`、`.mht` 或 `.mhtml`。

本工具只监听本机 `127.0.0.1`，不会把文件发送到互联网，也不需要安装 npm 依赖。

## 二、如何获取原始 HTML

### 方法 A：使用 Microsoft Word

建议使用桌面版 Word，不要使用 Word 网页版。

Windows 版通常按以下步骤操作：

1. 使用 Word 打开原始 `.doc` 或 `.docx`。
2. 选择“文件”→“另存为”→“浏览”。
3. 在“保存类型”中选择“网页（*.htm; *.html）”。
4. 选择一个单独的工作文件夹，然后保存。

macOS 版 Word 在“文件”→“另存为”中通常会提供“网页（.htm）”和“筛选过的网页”两个选项。经过实际测试，本项目可以处理这两种方式导出的 HTML。

建议优先使用普通的 **“网页（.htm）”**，以尽可能保留 Word 导出的样式和结构；如果希望获得相对精简的原始 HTML，也可以选择“筛选过的网页”。无论选择哪一种，转换后都需要对照原 Word 文档检查页面样式。

不要选择“单个文件网页（.mht/.mhtml）”，当前工具不处理这种格式。

### 方法 B：使用 WPS Writer

1. 使用 WPS Writer 打开原始 `.doc` 或 `.docx`。
2. 点击左上角“文件”或“菜单”。
3. 选择“另存为”。
4. 在文件类型中选择“网页文件（*.html; *.htm）”。
5. 选择一个单独的工作文件夹，然后保存。

不要选择名称以 `.~` 开头的临时锁文件。

### 原始文件整理建议

建议每份 Word 文档使用独立工作文件夹：

```text
某知情同意书/
└── 某知情同意书.html
```

## 三、转换方式

### 方式一：可视化版本（推荐）

macOS 可以双击：

```text
可视化版本/启动可视化版本.command
```

也可以在本项目根目录运行：

```bash
node "可视化版本/server.js"
```

启动后浏览器会打开：

```text
http://127.0.0.1:4173/
```

推荐操作流程：

1. 打开“Word HTML 处理”。
2. 点击“选择工作文件夹（推荐）”。
3. 选择包含 Word/WPS HTML 的文件夹。
4. 如果文件夹中有多个原始 HTML，在下拉框中选择需要处理的文件。
5. 确认或修改“生成文件名称”；只填写基础名称，不需要扩展名。
6. 点击“开始转换并校验”。
7. 所有检查通过后，保存 HTML 和 TXT，或者点击按钮复制完整内容。

使用“工作文件夹”方式时，结果会写回所选文件夹。同名文件不会被覆盖，而是自动增加 `(2)`、`(3)` 等编号。支持文件系统访问接口的浏览器会直接请求文件夹授权；在 macOS 上，如果当前浏览器不支持该接口，本地服务会调用系统文件夹选择窗口完成授权。

“生成文件名称”默认取源 HTML 去掉扩展名后的名称，允许在转换前修改。例如填写 `第三次`，会生成 `第三次_legal_permission.html` 和 `第三次_转码+转义.txt`。

也可以继续使用普通“选择 Word HTML”。由于普通浏览器文件选择不会提供源目录写入权限，这种方式生成的结果会进入浏览器默认下载目录。

可视化页面还提供：

- **HTML → TXT**：修改处理后的 HTML，再重新生成并校验 TXT；
- **TXT → HTML**：把 TXT 反向解析为 HTML，检查或继续编辑；
- **复制内容**：直接复制生成文件中的完整文字内容。

### 方式二：命令行版本

1. 把待处理 HTML 放入项目的 `输入/` 文件夹。
2. 在项目根目录运行：

```bash
node "脚本/处理WordHTML.js"
```

如果 `输入/` 中有多个 HTML，必须明确指定文件名：

```bash
node "脚本/处理WordHTML.js" "需要处理的文件.html"
```

每次运行前，程序会清空本项目的 `输出/` 文件夹，然后生成同一组六位编号的三个文件：

```text
原文件名_legal_permission_随机编号.html
原文件名_转码+转义_随机编号.txt
原文件名_处理报告_随机编号.json
```

输入文件不会被覆盖、移动或删除。

## 四、转换过程中会做什么

固定转换核心会执行并校验以下处理：

- 提取正文与必要样式，去除完整 HTML 文档外壳和 Office 专用元数据；
- 删除 `mso-*` 等仅供 Office 使用的声明；
- 删除浏览器不会执行的 Word 私有 `@list` 列表定义，仅保留正文段落上实际生效的 margin、缩进和列表文字；
- 删除所有图片节点、图片资源属性和 CSS 图片 URL，不读取或内嵌图片文件；
- 保留除图片以外的正文、段落、空段落、表格、粗体、下划线、颜色、字号、缩进、margin 和行高；
- 移除 `@font-face`、`font-family`、`<font face>` 等字体家族设置，让结果继承宿主页面或用户设备默认字体；
- 取消链接点击能力，但保留链接文字、颜色和下划线等可见效果；
- 给可见 URL 添加禁止内部换行规则；
- 生成合法 JSON 字符串，并检查两层 `core-data` 序列化安全；
- 验证 HTML 与 TXT 可以逐字符往返，且可见文字和非字体内联样式没有意外变化。
- 压缩 `<style>` 中因删除 Word 私有规则产生的连续空白行，不删除正文空段落。

转换核心不会根据视觉猜测删除空段落、重建编号、移动标题或擅自修改 margin。

## 五、输出文件怎么使用

### HTML

HTML 输出的固定结构是：

```html
<style>保留的排版样式</style>
<div class="legal-permission">正文</div>
```

它是正文片段，不是带有 `html/head/body` 的完整独立网页。应嵌入目标系统对应的正文区域。

HTML 可以继续人工修改，但修改后不要沿用旧 TXT。请在可视化页面进入“HTML → TXT”，重新生成并校验 TXT。

### TXT

TXT 顶层是一个合法 JSON 字符串，包含外层双引号、换行转义和 HTML 实体。例如：

```text
"&lt;style&gt;...&lt;/style&gt;&lt;div class=\"legal-permission\"&gt;..."
```

使用时必须复制完整内容：

- 不要删除最外层双引号；
- 不要手工删除反斜杠或换行转义；
- 不要先用普通文本替换工具再次转义；
- 不要直接修改 TXT 正文，应该修改 HTML 后重新生成 TXT。

### JSON 报告

命令行版报告记录输入哈希、输出哈希、文件大小、图片与链接处理数量，以及所有验收结果。只有脚本退出成功且报告中的检查全部为 `true`，结果才可以交付。

## 六、后续使用注意事项

1. **必须对照原 Word 调试样式。** Word/WPS 的页面布局模型和浏览器不同，分页、浮动图片、编号、表格宽度、首行缩进等可能在导出时发生变化。
2. **WPS 导出的 HTML 通常更复杂。** 大量冗余标签、重复样式或异常 CSS 可能来自 WPS 本身；本工具优先保证内容完整和传输安全，不承诺自动修复所有视觉问题。
3. **转换成功不等于视觉完全一致。** “校验通过”表示结构和内容没有发生无法解释的丢失，不表示可以跳过页面检查。
4. **字体由运行环境决定。** 工具默认移除原始字体家族，不嵌入商业字体文件；不同系统可能使用不同默认字体，因此换行和文字宽度可能略有差异。
5. **图片会被统一移除。** 输出 HTML/TXT 不包含图片节点或图片资源引用，以减少文本体积；圆点、方框等标记可以在目标页面中通过 CSS 重新实现。
6. **链接默认不可点击。** 这是知情同意书正文的安全规则；如果业务确实需要可点击链接，应先修改转换契约并重新验收。
7. **不要使用在线转码网站处理敏感同意书。** 本项目已经提供离线 HTML/TXT 往返，避免把正文上传给第三方网站。
8. **保存前注意文件名称。** 可视化工作文件夹模式不会覆盖同名结果；命令行模式则会在每次运行前清空项目 `输出/` 文件夹。
9. **页面服务修改后要重启。** 如果转换核心或本地服务代码发生更新，应关闭旧终端并重新运行启动器；只刷新浏览器可能仍使用旧进程缓存的核心代码。
10. **错误时不要绕过校验。** 页面会显示失败原因；命令行会在控制台输出错误。HTML 结构异常、图片引用未完全移除或 JSON 往返失败时，应先解决原因再交付。

## 七、常见问题

### 可以直接处理 `.docx` 吗？

不可以。请先使用 Word 或 WPS 导出 `.html` / `.htm`。

### 可以处理 `.mht` / `.mhtml` 吗？

当前不支持。请重新导出为普通网页 HTML。

### 为什么生成 HTML 和原 Word 不完全一样？

Word/WPS 在“另存为网页”阶段已经把文档排版转换为浏览器能够理解的 HTML/CSS。某些 Word 专用效果没有直接对应的网页实现，因此导出结果本身就可能发生变化。Microsoft 也建议导出网页后在浏览器中预览检查。

### 为什么删除了字体名称？

这是项目的默认规则，用于避免商业字体分发问题、跨设备字体缺失和 CSS 单引号导致的 `core-data` 截断。字号、颜色、粗体、斜体等仍会保留。

### 修改 HTML 后怎样得到新的 TXT？

打开可视化版本的“HTML → TXT”，上传或粘贴修改后的 HTML，点击“生成并校验 TXT”。不要直接修改旧 TXT。

### 项目复制到其他工程还能运行吗？

可以。脚本和页面都使用项目内相对路径。复制整个 `word转html处理方案/` 文件夹，并确保电脑已安装 Node.js 即可。
