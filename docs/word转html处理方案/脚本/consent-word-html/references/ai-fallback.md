# AI 受控回退说明

仅当固定脚本失败时读取并执行。本流程不是授权 AI 任意“优化”HTML。

## 处理原则

1. 输入文件永远只读；在同目录或用户指定目录创建带明确后缀的新文件。
2. 先记录失败校验、输入文件哈希、字节数和相关上下文，再提出最小修改方案。
3. 只处理导致脚本失败的结构。不要顺手清理、格式化、重排或美化其他内容。
4. 优先扩展固定脚本并补充回归用例；不要把一次性临时代码当成最终方案。
5. 如果无法证明文字、结构和视觉信息保持一致，停止并请用户确认。

## AI 可执行的白名单

- 识别 Word/WPS 导出的等价文档外壳变体，并将其映射到 `<style> + <div class="legal-permission">`。
- 识别新的图片节点、图片属性或 CSS 图片 URL 写法，并按固定规则移除；不得读取或内嵌图片文件。
- 识别合法的属性引号变体，并只把属性边界规范成双引号。
- 补充 JSON 和 `core-data='...'` 传输安全检查。
- 修复脚本对已知等价标签写法的解析，但不得改变标签正文、CSS 值或显示样式。

## AI 禁止执行的动作

- 按“看起来多余”删除空段落、空 span、`o:p`、换行或空格。
- 修改 margin、padding、line-height、text-indent、字号、字体、颜色、粗体或下划线。
- 根据截图猜测编号、标题层级、居中方式或列表结构。
- 把所有单引号直接替换成双引号；正文和 CSS 数据中的单引号必须保留并在 JSON 层写成 `\u0027`。
- 因为某个 Word 私有标签不认识就直接删除它。
- 在校验失败后手工修改报告为“通过”。

## 必做对比

生成候选结果后，至少比较：

- 可见文字指纹。
- `p/table/tr/td/th/b/strong/u` 标签数量，以及输入图片节点与输出移除计数。
- 是否已移除全部图片节点、图片属性和 CSS 图片 URL。
- 字体、字号、颜色、margin、缩进相关 CSS 值。
- 链接文字及原有视觉类名；只允许取消跳转能力。
- JSON 往返是否逐字符恢复候选 HTML。
- 模拟放入单引号包裹的 `core-data` 后是否完整读回。

## 交付门槛

AI 必须交付候选文件和差异报告，并明确列出：脚本为何失败、增加了哪条解析规则、哪些检查通过、是否存在无法证明的差异。存在未解释差异时不得把候选文件称为“无损结果”。
