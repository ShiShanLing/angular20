# 项目内置 `consent-word-html` 使用说明

## 用途

该 Skill 用于处理 Microsoft Word 导出的知情同意书 `.html` 或 `.htm` 文件，并生成：

- `legal_permission` HTML 正文片段。
- 已转码、转义的 TXT JSON 字符串。
- 机器可读的处理与校验报告。

它不会覆盖原始 HTML 文件。

## 在新任务中怎么告诉 AI

在以 `word转html处理方案/` 为项目根目录的 Codex 任务中输入或粘贴下面的内容。只需要把文件名换成这次要处理的 Word HTML 文件：

```text
使用 `脚本/consent-word-html/` 中的项目内置规则处理这个文件：

输入/word转html第二次测试.html

要求通过 `脚本/处理WordHTML.js` 固定入口执行，不覆盖原文件。完成后告诉我三个输出文件的绝对路径和校验报告摘要。如果脚本失败，按照 AI 受控回退说明处理，不要绕过校验。
```

所有路径都相对于项目根目录；移动整个项目文件夹后无需修改。

## 输入文件要求

- 输入应为 Word 导出的 `.html` 或 `.htm`，不是 `.docx`。
- Word 导出时产生的图片资源目录不参与转换，不需要复制到项目“输入”文件夹。
- 固定脚本会删除所有图片节点和图片资源引用；图片文件缺失不会影响转换。

## 项目输出

项目入口会在 `输出/` 文件夹中生成三个新文件：

```text
原文件名_legal_permission_随机编号.html
原文件名_转码+转义_随机编号.txt
原文件名_处理报告_随机编号.json
```

以上文件都是新文件，原始 Word HTML 保持不变。

## AI 完成后应当回复什么

AI 的回复必须包含：

1. 输入文件的绝对路径。
2. HTML 正文片段的绝对路径。
3. TXT 文件的绝对路径。
4. 校验报告的绝对路径。
5. 移除图片数量、禁用链接数量和裸单引号数量。
6. JSON 解析、逐字符解码、可见文字、内联样式、文档外壳、Word 私有 `@list`、全部图片和可点击链接检查是否通过。

不能只回复“已经处理完成”。

## 脚本失败时

脚本失败不代表 AI 可以临时换一种方式强行输出。AI 必须：

1. 停止自动交付。
2. 说明具体失败的校验项。
3. 阅读 `references/ai-fallback.md` 中的 AI 受控回退说明。
4. 只制作候选副本和差异报告，不覆盖原文件。
5. 不绕过校验，不把存在未解释差异的文件称为“无损结果”。

## 不允许 AI 擅自进行的修改

- 删除空段落、空格或换行。
- 修改 margin、缩进、字号、字体、颜色、粗体或下划线。
- 根据截图猜测标题、编号或列表层级。
- 直接全局替换单双引号。
- 删除无法识别的标签或样式。
- 覆盖原始 Word HTML。
