# Word 转 HTML 处理方案使用说明

## 文件夹用途

```text
word转html处理方案/
├── 输入/    放置 Word 导出的 HTML；图片资源目录不参与转换
├── 输出/    存放脚本生成的 HTML、TXT 和校验报告
└── 脚本/    存放处理入口和本使用说明
```

原始输入文件不会被覆盖。

脚本默认移除 Word/WPS 写入的字体家族设置，包括 CSS `font-family`、`@font-face`、HTML `<font face="…">`，以及 `font:` 简写中的字体名称。字号、粗体、斜体、颜色、缩进和行高继续保留；最终字体由页面继承样式或用户设备默认字体决定。

脚本也会精准移除现代浏览器不采用的旧式 Word/IE 排版声明：`layout-grid` 系列、`tab-stops` 和 `text-underline`。标准的 `text-decoration`、`text-align`、`text-justify`、`text-autospace`、分页、尺寸、边距和行高等可能影响实际展示的属性继续保留。

生成结果会移除 `<style>` 标签内部的 CSS 注释，并安全压缩 `<style>` 和元素 `style` 属性中的无意义空白。例如，选择器列表 `p.MsoNormal, li.MsoNormal, div.MsoNormal` 会变为 `p.MsoNormal,li.MsoNormal,div.MsoNormal`，声明 `{ margin: 0 }` 会变为 `{margin:0}`，相邻规则之间不再保留空格。后代选择器、多个属性值、函数表达式、CSS 字符串和转义字符中的必要空白会原样保留。Word HTML 初次转换完成后，整份正文片段中的全部 CR/LF 源码换行字符也会替换为普通空格。该规则只整理 HTML 源码，不删除 `<p>`、`<br>` 或空段落等实际页面结构；用户在后续 HTML → TXT 编辑流程中主动添加的换行仍按原样参与转码。

## 推荐：在新 Codex 任务中告诉 AI

把 Word 导出的 HTML 及其配套资源目录放入“输入”文件夹，然后向 AI 发送：

```text
使用项目内置的 `脚本/consent-word-html/` 固定规则处理这个文件：

输入/word转html第二次测试.html

要求使用固定脚本，不覆盖原文件。三个输出文件必须放入：
输出/

完成后告诉我三个输出文件的绝对路径和校验报告摘要。如果脚本失败，按照 `脚本/consent-word-html/references/ai-fallback.md` 处理，不要绕过校验。
```

以上路径均相对于 `word转html处理方案/` 项目根目录。移动整个项目后不需要修改路径；使用其他文件时，只替换提示词中的输入文件名。

## 直接运行脚本

先在终端进入 `word转html处理方案/` 项目根目录。当“输入”文件夹中只有一个 `.html` 或 `.htm` 文件时，可以运行：

```bash
node "脚本/处理WordHTML.js"
```

如果“输入”文件夹中有多个 HTML，需要指定文件名：

```bash
node "脚本/处理WordHTML.js" "需要处理的文件.html"
```

## 使用可视化版本

macOS 可以双击 `可视化版本/启动可视化版本.command`；也可以在项目根目录运行：

```bash
node "可视化版本/server.js"
```

启动后浏览器会自动打开统一页面，提供三种流程：

1. `Word HTML 处理`：选择 Word 导出的 HTML；脚本会统一移除图片引用，不需要选择 `.fld` 或 `.files` 资源文件夹。
2. `HTML → TXT`：上传处理后的 HTML，或者把第一步结果直接带入页面编辑，修改后重新生成转码加转义 TXT。
3. `TXT → HTML`：上传或粘贴 TXT，反向解析并下载还原后的 HTML。

在支持文件系统访问的 Chromium 浏览器中，推荐点击“选择工作文件夹”：页面会列出该文件夹中的 Word HTML；转换成功后，点击保存按钮即可把 HTML/TXT 直接写回该文件夹。遇到同名文件时页面会询问是否覆盖；只有选择确认才会覆盖，选择取消则保留原文件不变。普通“选择文件”方式仍使用浏览器默认下载目录。

选择 Word HTML 后，“生成文件名称”会自动使用源文件名（不含扩展名），可以在转换前修改。不要填写 `.html`、`.htm` 或 `.txt` 扩展名；页面会预览最终生成的两个文件名。

每一种流程都遵循以下规则：

- 失败时页面显示具体原因，不提供不完整文件。
- 成功时提供 HTML 和 TXT 两个下载按钮，并显示校验摘要。
- 文件只发送到本机 `127.0.0.1`，不会上传到互联网。
- 页面处理使用系统临时目录，不会修改命令行版的“输入”和“输出”文件夹。
- 每个生成结果都可以直接复制文件内的完整文字内容。

## 输入注意事项

- 输入必须是 Word 导出的 `.html` 或 `.htm`，不是 `.docx`。
- Word 同时生成的 `.fld`、`.files` 等图片资源目录不会被读取，也不需要放入“输入”文件夹。
- 输出 HTML/TXT 不包含图片节点或图片资源引用；圆点、方框等标记可在后续页面中通过 CSS 实现。

## 输出文件

每次处理使用同一个六位随机编号，在“输出”文件夹生成：

```text
原文件名_legal_permission_随机编号.html
原文件名_转码+转义_随机编号.txt
原文件名_处理报告_随机编号.json
```

处理报告必须确认 JSON、逐字符解码、全部源码换行字符移除、CSS 无意义结构空白压缩、字体家族设置移除、Word 私有 `@list` 规则和旧式 Word/IE CSS 声明移除、图片引用移除、可见文字、其余内联样式、文档外壳和链接检查全部通过。

## 失败处理

- 不允许绕过失败校验后强行交付。
- AI 必须读取项目内的 `脚本/consent-word-html/references/ai-fallback.md` 受控回退说明。
- 不允许 AI 擅自删除空段落或修改 margin、缩进、字号、字体、颜色、编号和标题结构。
- AI 只能创建候选副本及差异报告，不能覆盖“输入”文件夹中的原文件。
